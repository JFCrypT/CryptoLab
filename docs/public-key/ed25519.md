# Ed25519 digital signatures

CryptoLab uses `cryptography` for pure Ed25519 signing and verification. Ed25519 is not
reimplemented manually.

The project supports:

- local key generation;
- PKCS#8 and SubjectPublicKeyInfo PEM serialization;
- raw 32-byte key inputs for RFC vector validation;
- messages from UTF-8 text, hexadecimal bytes, or files;
- 64-byte signatures;
- signature verification with exit code `4` for an invalid signature.

## Key generation

```bash
cryptolab public-key ed25519 generate \
  --private-key-out ed25519-private.pem \
  --public-key-out ed25519-public.pem
```

## Signing and verification

```bash
cryptolab public-key ed25519 sign \
  --private-key-file ed25519-private.pem \
  --message-text "CryptoLab"

cryptolab public-key ed25519 verify \
  --public-key-file ed25519-public.pem \
  --signature-hex SIGNATURE \
  --message-text "CryptoLab"
```

Pure Ed25519 signatures are deterministic for a fixed key and message. This contrasts with
the RSA-PSS profile used by CryptoLab, which includes a 32-byte random salt.

## Signature versus MAC

A digital signature uses a private signing key and a distinct public verification key. A
MAC such as HMAC-SHA-256 uses the same shared secret for tag generation and verification.
Therefore, any HMAC verifier can also generate valid tags; HMAC is not a digital signature.

```bash
cryptolab --explain public-key compare-signatures
```

A valid signature proves possession of the corresponding private key. It does not, by
itself, prove the real-world identity of the key holder or provide confidentiality.
